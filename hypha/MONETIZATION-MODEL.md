# 蛮有味 · 变现模型（纯 CPS）— 反广告前提下的单位经济

> 配套文档：`hypha/PRODUCT-VISION.md`（战略层）、`hypha/ARCHITECTURE.md`（工程层）。
> 本文回答一个具体问题：**在「排序不出卖」的信任内核下，LLM 每 query 的成本靠什么覆盖**。
> 结论（2026-08-10 锁定）：靠**纯 CPS / 到店核销分润**单一线；用户订阅已砍掉、透明赞助位暂不接——二者均与推荐排序解耦。
> 所有数字为〔估〕（基于公开定价与合理假设的估算，非精确测算）。

---

## 0. 总原则（不可动摇）

- **排序不出卖**：Agent 的推荐排名永不被任何出价、赞助、分润关系影响；可验证。
- **防火墙分离**：先由 Agent 独立生成推荐，再把商业链接/券「挂」在结果之后，绝不反向注入排序。
- **变现 ≠ 广告**：本文所有收入来自「用户付费买服务」或「真实发生的交易抽成」，不卖曝光、不卖排名。

---

## 1. CPS / 到店核销分润

### 1.1 是什么
商户按**真实到店成交**向平台分润（效果付费）。用户通过 Agent 推荐 → 到店出示券/核销 → 平台从这笔交易里抽固定比例或固定金额。**没人去吃，平台不分钱**——这天然和「反广告」兼容，因为分润只看结果、不买排名。

### 1.2 产品流（具体）
1. 用户说「财大南湖周边附近便宜的宵夜」→ Agent 独立排序给出推荐（排序不受任何商户付费影响）。
2. 推荐卡片里，参与了分润网络的商户，其卡片下方挂一个**明确标注「可核销优惠」**的按钮（标注本身即透明，不改变排序位置）。
3. 用户到店 → 出示核销码 → 商户端核销 → 标记转化。
4. 结算：平台按约定比例/金额从该笔交易抽佣。

### 1.3 具体例子（〔估〕）
- 商户：老樊城襄阳牛肉面（客单约 ¥25）。
- 分润：固定 ¥2/核销单，或 5% ≈ ¥1.25/单。
- 含义：这家店不需要「花钱排前面」，它只是「被推荐后、用户真去了、平台分一点」。

### 1.4 为什么碰不到排序（防火墙）
- 推荐集由 Agent 基于信任信号（评分/距离/价位/真实点评）生成；
- 分润链接是**结果后处理**：只在已入选的卡片上挂「可核销」标，不增不减入选资格；
- 若某商户不在分润网络，它照样可凭信任入选推荐（只是没挂核销标）——**分润网络 ≠ 推荐资格**。

### 1.5 已有基建（关键：不用从零建）
- `M14 核销后台`（`redemption.js` + `ui/redeem.js` + `redemption.test.mjs`）已落地：normalizedCode / canRedeem 幂等 / 按码定位 / 核销置位。
- `reward.claim` / `reward.view-wallet` / `CouponIssuer` 已能发真实券、管券包。
- `analytics.track` 已剥离 PII、可统计转化事件。
- **缺口**：商户侧签约与分润结算（商业动作，非技术），以及「推荐卡片挂核销标」的前端接线。

### 1.6 收入测算（〔估〕）
- 覆盖总成本（含运维 ~¥500–1000/月）需：约 **250 单/月 @¥2**（或 30 商户 × 8 单/月）。
- 财大南湖周边 DAU ~2100 时，核销率仅需 ~5% 即可覆盖——门槛不高。

---

## 2. 订阅 / 会员 ——【已砍掉，2026-08-10 Robin 决策】

**不作为变现线。** 理由：校园付费意愿低，且订阅并非信任必需；成本覆盖改由 CPS 单一承担。
保留此节仅为记录决策可追溯——原设想（用户付费买高级筛选/跨会话记忆/无赞助体验）不再落地。
注：跨会话口味记忆作为产品体验仍可在免费层提供（localStorage），只是不再与「付费」绑定。

---

## 3. 组合与成本覆盖（〔估〕汇总）

| 收入线 | 状态 | 是否碰排序 | 覆盖成本角色 |
|---|---|---|---|
| CPS / 到店核销 | **唯一活跃线** | 否（结果后挂） | 主收入 + 成本覆盖 |
| 用户订阅 | **已砍掉（2026-08-10）** | 否 | — |
| 透明赞助位 | 后备（暂不接） | 否（独立标注位） | 可选后备，非主轴 |

单位经济结论：校园规模下 LLM 推理成本 ~¥100–300/月（可忽略），总运营成本 ~¥500–1000/月；
**成本覆盖现完全由 CPS 承担**——需 ~250 单/月 @¥2（或 30 商户 × 8 单/月，核销率 ~5%）。
这意味着：**商户签约网络 + 核销转化体验成为单位经济的唯一命门**，须作为重构后的头等优先。

---

## 4. 防火墙 / 信任保护（必建，非可选）

1. **推荐与商业化物理分离**：Agent 推荐逻辑代码中不导入任何「商户付费」字段；分润/赞助信息在渲染层后挂。
2. **CPS 商户集 ≠ 推荐资格**：未签约分润的商户照样可凭信任入选；签约商户不因分润获得排序加权。
3. **可验证**：对外承诺「排序算法不接收付费信号」，并提供可核查说明（如开源排序权重口径 / 审计日志）。
4. **标注强制**：任何带商业关系的卡片/位必须明示「赞助 / 可核销优惠」，未标注即违规。

---

## 5. 透明赞助位（后备，可选，本次暂不接）

仅在 CPS+订阅跑通、信任被验证不破后，作为**可选后备线**考虑：
- 独立、带「赞助」标的展示条带/品类冠名，**永不进推荐排序**；
- 收入可预期（包周/包月固定费），比 CPS 更好卖给本地小商户；
- 代价：产品带广告味，轻微稀释纯净度——故早期不接。

---

## 6. 结论

- 「反广告」= **排序不出卖**（已锁定），不是「绝不商业化」。
- 变现靠 **纯 CPS（真实转化分润）**；订阅已砍掉、赞助位暂不接——CPS 单一承担成本覆盖，须优先建设商户网络与核销转化。
- 成本侧已被证明可承受（DeepSeek 极便宜 + 规则引擎兜底 50–70% 简单 query）。
- 本项目**已有核销/券/埋点基建**，CPS 落地主要是商户签约 + 前端挂标，非重技术投入。
- 透明赞助位留作后期后备，早期不接。
