## 2. 「从网上大数据获取真实描述」 — 风险与路径(此节是 Robin 明确让我「先写计划」的核心)

### 2.1 真实风险清单

| 风险类型 | 说明 | 严重度 |
|---|---|---|
| **商誉 / 著作权** | 抓"用户评价"原文 → 露骨引用违反反不正当竞争; 改写也未必脱敏 | 🔴 高 |
| **时效性** | 90% 商户 1–2 年内有"装修/关门/换老板"变动, 抓的内容极易过时 | 🔴 高 |
| **数据真实性** | 大众点评/小红书充斥刷评与软广, 一旦搬进自家应用, 信任破产 | 🔴 高 |
| **违反产品反广告原则** | PRD 锁定"排序不出卖", 第三方评价进了"推荐理由"就会变成"借用他人嘴说话" | 🟡 中 |
| **API 接入门槛** | 大众点评/小红书无官方公开 API, 爬虫还要应对反爬, 工作量大且收益低 | 🟡 中 |

### 2.2 三条可行路径(对比)

#### 路径 A — 「不联网填空」✅ 推荐
- **做法**: 311 条新增商户只填"店名 / 街道 / 招牌菜 / 菜系"(开放常识可推断的), 描述 / 人均 / 营业时间 / 电话 留 null, UI 显式标"信息待补"
- **优势**: 零法律风险, 零数据失真, 工作量最小
- **劣势**: 短期卡"信息密度低", 但诚实 == 信任
- **可行性**: 极好。我已掌握武汉高校周边开放式常识 + 99 家店同类派生

#### 路径 B — 「DeepSeek 单次摘要 + 人工审计」🟡 备选
- **做法**: 把 311 条待补的店名 + 街道 + 招牌菜打包给 DeepSeek, 让它生成 1–2 句"事实性描述"(只描述"卖什么 / 特色菜是什么", **禁止带评价词**); 结果人工 / 我自己再筛一遍, 删掉任何带"必吃 / 强推 / 不错"等评价词
- **优势**: 信息密度比 A 高
- **劣势**: 仍有事实性风险(LLM 编造似是而非的细节); 需后端配置 DeepSeek Key; 需要单次审计
- **可行性**: 中。需要约 1 小时人工审计 311 条

#### 路径 C — 「实地采集 + 一次性 LLM 校对」🟢 最稳但最慢
- **做法**: 设计一份 30 秒/店的采集模板(店名 / 招牌菜 / 大致人均 / 营业时间 / 1 张实拍门头), 你和同学周末扫街 100–200 家; 然后一次性 LLM 结构化校对入库
- **优势**: 全是真数据, 反广告原则友好, 还能反过来驱动 CPS 商家签约
- **劣势**: 你的时间成本(周末半天才能扫 50 家, 撑死 100 家/周)
- **可行性**: 高, 但耗时。**可作为后续长期工作流**

### 2.3 我的建议

**默认走 A**(诚实填空 + 显式"待补"标记)。311 条"真不知道"的字段标 `pending: true`, UI 上特殊样式(灰、缩), 等用户哪天路过去吃 一补一行。如果你接受,我下一步就在 A 路径内出 1000+ 方案。

**B 仅在你接受 1 小时人工审计成本后再启动。**

**C 长期有意义, 但不应该阻塞当前 UI 改造。**

## 3. 地图页 UI / 交互重设计方向

### 3.1 现状(对照)

- M9 地图 = 纯 SVG 等距投影, 全 590 标记点
- 标记点大小统一, 没有聚类, 拥挤区域(光谷 / 江汉路)严重重叠
- 没有"区域色块" / "街道维度"概念
- 跳转: 点标记 → 详情
- 顶部一个「返回」+ 入口路由

### 3.2 优化方向(可分阶段, 推荐分两期)

#### 第一期 · 「首屏即地图」 1–2 天工作量
- **目标**: 进首页就是地图, 视觉冲击力强
- **改动**:
  - `main.js:16` `let view = 'map'` 默认
  - 地图全屏(`position: fixed` 顶层), 旧 home 改为顶部悬浮的"对话胶囊"(可折叠)
  - 地图顶部加 2 个 zone 过滤 pill: 武汉全城 / 财大南湖周边 (与两类分区模型一致)
  - 标记点放大到 12–14px, 加主推色 + 半透明阴影
- **风险**: 中(改 default view)。需要补个 "上方对话胶囊 → B 形态"的入口

#### 第二期 · 「街道聚合 + 真实地图」 3–5 天
- **聚类**: 拥挤区域(光谷)同一像素半径内 >3 个点 → 变成数字徽章, 点击展开
- **街道色块**: 用地址里的"街道"做二阶聚合, 地图上画半透明色块(财大小吃街 / 光谷天地 / 江汉路…)
- **真实地图(可选)**: M11 高德 Key 安全接入已就绪, 把当前等距投影换成真地图, 标记点用高德 POI marker
- **关键交互**: 选 zone → 街道 → 单店, 三级缩放 drill-down

### 3.3 不做的事

- 不做"标记点按销量排名排序" — 违反反广告原则
- 不做"街道美食热度热力图" — 缺数据, 强行做等于编造
- 不做"AR 寻店" — 没必要
