### D-20260810-01 · LLM 为产品地基（锁定 Path B）
- **日期**：2026-08-10
- **决策**：产品必须以智能体+大模型（DeepSeek）为基座。自有 Node 后端（:8799 类）跑 DeepSeek tool_calling（ReAct），复用 10 工具+FSM+provenance 契约，前端零改动切 `setBackend('server')`；不依赖被 BLOCK 的共享 Hypha 3000 设施。规则引擎（intent-parser 关键词/正则/口语同义词）只是当前在跑的降级态/价值探针，退为兜底/熔断层。
- **理由**：Robin 纠正此前"先证价值再谈 AI 原生"的临时判断。DeepSeek Key 已提供（按红线仅存于服务端 env，不入库；V4 Flash，链路实测可达），LLM 基座可行性已实证。成本极便宜（≈2 分钱/次），推理成本不构成瓶颈。
- **替代方案（及为何放弃）**：① 共享 Hypha 3000 真·3000 原生运行时 —— 经 2026-08-10 主代理复验，domainPack 内联 `source:http` 工具未注册进 ToolManager、MCP 工具恒为 `external_effect` 被拒、写动作超天花板、governedSideEffectLevel 无运行时开关能把工具提到可用级；唯一途径改 `~/opt/hypha` 源码+重启（共享设施，需授权），已放弃作为主路径。② 客户端直连 + BYOK —— 普通用户无 Key、构建注入 Key 违反红线"密钥不进前端包"，放弃。
- **影响 / 后续**：后端持 Key(env)，客户端不直接持 Key；落地路线 = Path B。

### D-20260810-02 · 反广告 + 纯 CPS 变现（锁定）
- **日期**：2026-08-10
- **决策**：反广告=排序不出卖（信任内核，锁定，可验证）；变现=纯 CPS / 到店核销分润（单一线）。用户订阅已砍掉（校园付费意愿低且非信任必需）；透明赞助位暂不接（后备，非主轴）。
- **理由**：核心判断——"成本包不住"是收入端问题非成本端（推理极便宜，缺口在总运营成本 ~¥500–1000/月 + 零收入）；瓶颈是增长/adoption，不是 AI 贵。排序出卖会摧毁信任内核。
- **替代方案（及为何放弃）**：用户订阅制 —— Robin 决策校园付费意愿低且非信任必需，砍掉。
- **影响 / 后续**：成本覆盖完全由 CPS 承担 → 商户签约网络 + 核销转化体验成为单位经济唯一命门。文档 `hypha/MONETIZATION-MODEL.md`。

### D-20260811-01 · 数据层补全（确定性派生 + 真实核验注入）
- **日期**：2026-08-11
- **决策**：`scripts/normalize-data.mjs` 增强派生全字段（人均数值、推荐菜、口味/口味标签、环境、环境/服务评分、适合场景、标签、等待时长、点评摘要、资料置信度）；联网核验 40 家武汉真实名店（早/宵夜/湖北菜/火锅四类），匹配不上的注入为 `source:'web-verified'` 真实商户。重生成 `h5/src/data/merchants.js` = 625 家全字段商户（583 estimated + 41 verified + 1 partial）。
- **理由**：原数据每层店仅收集极少维度。既有 590 家多为合成/编辑数据，真实品牌联网研究仅匹配 7 家 → 确定性补全全部 590 + 注入 40 真实核验品牌作 verified 核心。
- **替代方案**：直接硬编码伪造真实品牌数据 —— 违反数据完整性红线（不编造），否决。
- **影响 / 后续**：`estimated` 商户口味/环境为按品类算法推导，已诚实标注"待核验"（`needsEnrichment:true`）；后续接探店采集可升级为 verified。

### D-20260811-02 · 算法层透明化（逐店理由 + 推理时间线）
- **日期**：2026-08-11
- **决策**：新增 `hypha/implementation/src/explain.js` 确定性引擎（无 LLM），为每家店生成一句话 `reason` + 可解释 `factors`（品类对味/口味合拍/预算内/高分口碑/离你近/真实核验/招牌硬菜/可领券/场景合适/资料待核验）+ 权重拆解。`intent-parser` 新增 `mood`/`taste` 抽取；`discovery-engine` 附 reason/factors；`orchestrator` 决策更具体 + 时间线新增「为什么推荐这家」步骤；`runtime.projectMerchant` 透传富字段 + explain；`agent-loop`(LLM 路径) 同样产出 factors；前端 `reasoning.js` 卡片显理由+因子标签、时间线渲染"为什么"，`detail.js` 补全富字段。
- **理由**：原智能体不解释推荐过程与结果推导（无推荐原因），Robin 明确要求完整呈现推理过程与推荐理由。
- **影响 / 后续**：7 套后端单测全绿（~96 断言）+ 新增 `reason.test.mjs`（27 断言）。实测 `MYWO_DATASOURCE=wuhan` 下 `POST /run` 主推带 5 因子 + 决策理由 + 时间线 why 步骤。

### D-20260812-01 · 生产 LLM 选型与部署拓扑
- **日期**：2026-08-12
- **决策**：生产环境**优先国内 LLM**（DeepSeek / 智谱付费档 / 通义 / 豆包 / Kimi）→ 后端放国内云，零跨境、合规、稳定、便宜；免费档仅用于开发联调。要用海外顶级模型则**后端出海**（HK/新加坡/东京节点直连），用户照常连 Robin 后端、不需梯子、不需额外中转；**绝不**把后端放境内再翻出去调 Google/Gemini（不稳 + 合规灰区，商用不建议）。
- **理由**：① 用户不需要梯子——LLM API 由后端调，用户只连 Robin 自己的后端；② 不需要"给用户用的中转站"——后端本身已是用户↔LLM 代理，问题实质是"后端部署在哪、怎么出网"。海外免费档（Mistral 1 RPS/eval-only、Gemini 免费 RPD 限额且中国大陆不在支持地区、Groq/Cerebras 托管 Llama ~14,400 RPD 但无 SLA 且海外节点境内服务器连不上）都不扛真实高并发，规模一来必付费（但极便宜）。
- **替代方案（及为何放弃）**：境内后端 + 代理翻出调 Google/Gemini —— Google 按 IP+地区双重封锁境内访问，不稳且踩合规灰区，商用否决。
- **影响 / 后续**：待 Robin 拍板 —— ① LLM 客户端做多供应商可插拔（DeepSeek/智谱/Gemini/Mistral 一套接口、默认国内可切海外）；② 或先接 DeepSeek 付费档跑真实调用测成本/延迟。
