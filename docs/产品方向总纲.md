# 江城 · 财大校园经济 —— 产品方向总纲

> 锁定日期：2026-08-03。本文记录已拍板的方向性决策，是后续所有执行文档的母文档。

## 一、一句话定位

用一份**民间新生手册**把财大 2026 级新生聚成社群，再以社群为渠道分发**美食地图**，最终在有了真实流量后做商家变现。

> **手册是钩子，社群是资产，美食地图是二次传播与未来变现。**

## 二、已锁定的决策

1. **两个产品，一套后台。** 新生手册与美食地图是两个独立入口（各自域名 / 视觉 / 定位），但共享同一套数据层与 API。对外不混淆，对内不重复。
2. **执行顺序：手册优先 → 建社群 → 美食地图在社群内传播 → 变现后置。** 不抢 9 月窗口硬变现。
3. **资源现实：有学生合伙人 + 已有宣传方法。** 走"有人"路径，手册可在 9 月窗口前上线并分发。
4. **平台 / 12 模块方案已废弃。** `platform/`（AI 生成的空壳脚手架）已于 2026-08-03 删除，可从 git `a83b3f8` 还原。不再做"全校日常大平台"。

## 三、为什么是两个产品，不是合并

- **需求节奏不同**：手册是一年约 5 周的脉冲需求（只用一次）；美食地图是常年在线、反复回来。
- **定位混杂伤传播**：把常年产品绑死在只有 9 月才有人看的入口上，会同时毁掉两边。
- **各自独立部署、共享后端**：解决"两个站两套代码做两遍"的老问题（这也是 8 月一度把两者合并成大平台又推翻的原因）。

## 四、两个产品定位对照

| 维度 | 新生手册 | 美食地图 |
| --- | --- | --- |
| 角色 | 先发钩子 | 后发，社群内传播 |
| 需求节奏 | 脉冲（9 月） | 常年 |
| 用户 | 读完即走 | 反复回访 |
| 内容 | 16 页已齐（约 1.1 万字） | 622 条商户数据已齐 |
| 是否需要后端 | 否（静态即可） | 是（地图 + 数据 API） |
| 变现 | 不硬赶 | 后置，有流量再谈商家 |

## 五、本期明确不做（边界）

- 不做 12 模块大平台、UGC、二手、动态圈、积分等"无人即用即空壳"的功能。
- 不现在接 Supabase / 自建后端（等美食地图要上时再建统一 API）。
- 不抢 9 月窗口做商家收费。

## 六、下一步

- **近期**：按《手册体验改版计划》打磨手册前端，尽快上线抓 9 月窗口。
- **同期**：按《增长与社群运营计划》铺学生合伙人与分发渠道。
- **之后**：社群成型后，按《架构方案 · 两个产品一套后台》起美食地图（复用统一数据层）。
