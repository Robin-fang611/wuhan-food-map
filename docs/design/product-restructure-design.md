# 蛮有味 · 界面重构设计（围绕美食智能体 + 本地生活）

> **状态**：DRAFT（Robin 2026-08-15 反馈 Q3 的细化草案，待拍板）
> **目标**：让用户聚焦核心价值——**用智能体/搜索匹配符合个性化需求的店铺** + **强本地生活特征**（小吃街、流动摊贩——高德没有的数据资产）；商业化模块保留但重新编排。
> 关联：docs/SPEC.md §15 Q3/Q5、hypha/PRODUCT-REQUIREMENTS.md §3.1（对话优先 B 形态）

---

## 1. 设计原则（一句话版）

1. **首页只做一件事：帮用户决定「今天吃啥」**——对话/搜索入口 + 情境快捷 + 本地生活抓手。
2. **本地生活是差异化护城河**：小吃街地图、流动摊贩（206 家高德没有）、用户上传采集闭环——这是大众点评/美团做不到的。
3. **商业化不抢占心智**：签到/抽奖/任务/券包是留存与活跃手段，收进「我的」与二级页，不在首页堆砌。
4. **渐进式智能体体验**：输入 → 分析过程可视化 → 推荐结果（含「为什么」），让用户感知 Agent 在工作（对应 SPEC §15 Q1/Q2 的双轨与实事求是）。

---

## 2. 现状问题（实查，2026-08-15）

- 首页一屏内容：英雄区（意图栏+4 chips+入口条）+ 每日签到 + 幸运抽奖 + 新人任务 + 发现（列表）+ 榜单 + 我的券包 + 页脚说明——**9 个模块抢一屏**，核心的「问智能体」只占约 1/5。
- 签到/抽奖/任务与「吃啥决策」无关，用户进首页被大量运营模块分散注意力。
- 本地生活资产（流动摊贩 206 家、财大南湖 185 家）散落在长列表里，没有场景化入口（「附近」「小吃街」）。

---

## 3. 目标信息架构（4 个一级入口）

```
┌────────────────────────────────────────────┐
│  底部 Tab（4 个，拇指可达）                    │
│  [🍜 今天吃啥] [🗺 附近/地图] [🧾 我的] [🎁 福利] │
└────────────────────────────────────────────┘
```

| Tab | 定位 | 内容 | 商业化元素 |
|-----|------|------|-----------|
| **今天吃啥**（首页，唯一主界面） | 美食智能体 | ① 顶部对话入口（大输入框 + 情境 chips：心情不好/想省钱/带人吃饭/不知道吃啥/健身轻食）② 最近一次推荐回顾（老用户回来继续聊）③「为什么推荐」信任说明（排序不出卖）④ 本地生活速览（今天的小吃街/附近 3 家） | 无（纯核心功能） |
| **附近/地图** | 本地生活 | ① 地图（高德，流动摊贩特殊标记「摊」）② 小吃街场景卡片（财大小吃街/时尚城/南湖）③ 按片区/场景筛选（宵夜/过早/聚餐）④ 用户上传入口（拍照/填表 → 智能体校验入库） | 商家「可核销」标（CPS，渲染层后挂） |
| **我的** | 账号与资产 | 登录/账号、我的收藏、我的口味档案（可编辑）、浏览历史 | — |
| **福利** | 商业化集中地 | 每日签到、幸运抽奖、新人任务、我的券包、核销记录、商家入驻（未来） | 全部运营/商业模块集中于此，与核心决策隔离 |

**关键决策**：
- 「福利」Tab 承接全部游戏化/商业化模块——**签到/抽奖/任务从首页彻底移出**，但入口显眼（Tab 常驻），活跃用户不流失。
- 「附近/地图」承接本地生活：地图 + 小吃街场景 + 上传采集（现有 uploadShop 从地图页浮动按钮升级为一级能力）。
- 「今天吃啥」首页重构为「对话优先」：输入框即主角；首次用户给情境 chips + 「不知道吃啥」兜底；回访用户给上次推荐回顾 + 口味档案提示（越用越懂你）。

## 4. 首页（今天吃啥）线框

```
┌──────────────────────────────────────────────┐
│ 蛮有味 · 武汉好吃的，真人探过的                 │
│ ┌────────────────────────────────────────┐   │
│ │ 今天想吃啥？说一句话，Agent 帮你定  [问→] │  ← 大输入框（主角）
│ └────────────────────────────────────────┘   │
│ [心情不好] [想省钱] [带人吃饭] [不知道吃啥] [健身轻食] │  ← 情境 chips
│                                              │
│  ── 信任说明 ────────────────────────────    │
│  真人探过 · 排序永不被出价影响 · 可审计推理      │
│                                              │
│  ── 继续上次 ────────────────────────────    │
│  [上次聊到：老樊城襄阳牛肉面 ★]  [再聊聊 →]      │  ← 回访抓手
│                                              │
│  ── 今天附近 ────────────────────────────    │
│  财大小吃街（185 家 · 含流动摊 62）  [去看看 →]  │  ← 本地生活速览
│  时尚城 / 南湖夜市 ···                        │
│                                              │
│  [🍜 今天吃啥] [🗺 附近/地图] [🧾 我的] [🎁 福利] │  ← 底部 Tab
└──────────────────────────────────────────────┘
```

**对话 → 推理页（现有 ReasoningPage 增强）**：
1. 提交后立即渲染「Agent 分析中」步骤骨架（理解意图 → 检索数据库 → 匹配条件 → 排序权衡 → 生成推荐，脉冲动画）；
2. 结果返回后**逐步点亮**真实推理步骤（每步显示实际内容：片区/关键词/命中数/为什么推荐），让用户感知智能体在后台分析（对应 Q1 的「渐进式」诉求）；
3. 双轨：脚本结果标记「确定性推理 · 可审计」；LLM 升级结果标记「AI 深度分析」；无匹配时**诚实空态**（不硬凑）。

## 5. 本地生活深化（Q5）

- **流动摊贩资产化**：allMerchants 已有 206 家 web-stalls（坐标 null 未伪造），地图页用「摊」徽章区分；引导用户上传定位补全（拍照 → 智谱 GLM-4V-Flash 识别摊贩/菜品 → 高德无 POI → verified_stall 入库，见 vision-adapter-design.md）。
- **小吃街场景卡**：财大小吃街/时尚城/南湖夜市等场景聚合（按场景看整条街的店 + 摊），「今晚逛哪条街」成为二级入口。
- **上传采集闭环**：用户上传（文本 + 照片）→ 智能体校验（高德 + 视觉）→ 入库/待核验 → 治理（S5 已具备）→ 数据反哺推荐。
