# 第 3 轮交互体验优化：搜索与反馈

## 本轮目标
打磨高频交互路径中的细节反馈，让搜索、清单、空状态更接近原生 App 的体验。

## 问题清单

### P1 · 搜索框点击键盘「搜索」键无响应
- **现象**：搜索浮层中的输入框设置了 `enterkeyhint="search"`，但 iOS / 安卓键盘右下角出现的「搜索」按钮点击后没有任何反馈（没有 form，也没有监听 Enter）。
- **根因**：只监听了 `input` 事件做防抖搜索，未处理键盘提交。
- **修复方案**：在 `openSearch()` 中为 `#searchInput` 增加 `keydown` 监听；`Enter` 键触发 `doSearch()` 并让输入框 `blur()` 收起键盘；`Escape` 键关闭浮层（已存在）。
- **验收标准**：WebKit 模拟中按下 Enter 后搜索结果刷新且输入框失焦；e2e 搜索链路仍通过。

### P2 · 必读清单 8/8 后缺少完成反馈
- **现象**：首页「开学前必做八件事」全部勾选后，进度条填满，但没有文字或动效告诉用户"已完成"。
- **根因**：只更新了进度条和计数文案，缺少完成态提示。
- **修复方案**：当完成数达到 8 时，把 `mustnote` 文案改为「✓ 全部完成 · 开学稳了」，并给 `.mustbar-fill` 加一个 0.3s 的轻微色块闪烁（用 CSS 动画，尊重 reduced-motion）。
- **验收标准**：勾选第 8 项时，文案切换为完成态；刷新后仍保持。

### P2 · 搜索空状态引导可以更直接
- **现象**：搜索无结果时只显示"没找到 ××× 相关内容"和进群链接，没有告诉用户还能怎么找。
- **根因**：空状态文案过短，未给出替代动作。
- **修复方案**：空状态增加一行"试试更短的关键词，或按下方进群直接问"，并保留进群入口。
- **验收标准**：空结果页文案完整、进群入口可点。

## 影响范围
- `handbook/js/app.js`：搜索 Enter 响应、清单完成态
- `handbook/css/baibaoxiang.css`：清单完成态样式

## 验证方式
1. `node tools/e2e-check.js`：搜索链路、必读清单通过
2. WebKit 手动验证：搜索框 Enter 收起键盘、清单 8/8 文案变化
